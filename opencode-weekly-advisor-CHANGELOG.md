# Changelog — Pipeline `opencode-weekly-advisor`

Fichier indépendant de la spec (séparé le 14 août 2026, v5.26). Le corps de la spec (`opencode-weekly-advisor`) fait foi ; ce fichier trace l'historique des décisions.

- **v6.0.a** (15 août 2026, revue d'autonomie + rename) : spec `opencode-weekly-advisor-5` → `opencode-weekly-advisor` (le « 5 » datait du pipeline v5.x — obsolète en v6.0 ; aucune référence résiduelle dans les README/CHANGELOG/spec). **Doctor** : `project_root` sans `.opencode/` → **problem exit `2`** (sentinelle d'installation — la config de distribution du kit est neutralisée en placeholder `/path/to/...` ; un clone non adapté reçoit un blocage explicite, plus jamais un warning silencieux qu'un LLM peut omettre — observé : « Kit OK » avec placeholder avant le fix) ; warning « config introuvable » émis **seulement sans `--config`** (le plugin le passe toujours → plus de warning fantôme à chaque doctor). Spec §0/§1/§12 mises à jour (les claims restants de « `project_root` == répertoire d'exécution » étaient caducs depuis v6.0 : cwd = moteur ≠ project_root). **Config du kit** : `project_root`/`output_dir` neutralisés (le chemin du poste de dev commité fuyait des infos personnelles et trompait le clone). **README kit réécrit** : quickstart 6 commandes, URL du repo, install `[dev]` (sans `[dev]`, `pytest` absent — échec réel mesuré sur clone), table des prérequis avec commandes d'install (`opencode`, `uv`, `uv tool install harness-eval` — paquet PyPI, pas npm), `--model` dans la commande doctor (sinon échec sur poste neuf sans modèle configuré), note `bun` optionnel (shim runtime — vérifié : plugin OK sans `package.json`, non versionné). Validé : **clone frais GitHub → install → sentinelle exit `2` → adaptation → doctor exit `0` → 171 tests verts** ; miroir Adeo synchronisé (171 tests verts).
- **v6.0** (15 août 2026, migration Adeo → layout kit : plugin enveloppe + agent tools) : toute la mécanique déterministe passe des commandes bash de l'agent au **plugin enveloppe** `.opencode/plugins/weekly-advisor.ts` — **13 tools `weekly_*`** (run, releases, audit-candidates, show-session, harness, insights, draft-candidates, report-prep, report-blocks-draft, report-assemble, commit-draft, self-cost, doctor), un par sous-commande CLI, qui invoquent le moteur via `$WEEKLY_PYTHON` ?? `<worktree>/.venv/bin/python` (venv racine du repo, gitignoré). **`bash: deny`** : plus d'allowlist, l'agent n'a aucun besoin de bash (v5.23 → caduc). **Ancre auto** : `<output_dir>/anchor-last.txt` lu/créé par le plugin — l'agent n'a plus aucun calcul de temps (le `RUN_TIME=$(date …)` de l'agent disparaît). **Moteur déplacé** : `weekly-advisor/` racine → `.opencode/plugins/weekly-advisor-engine/` (config résolue par le plugin dans le moteur). Contrat cron allégé : plus rien à mettre sur PATH (résolution interne au plugin). Validé par **run complet exit 0 sur Adeo le 15/08** (12 étapes, 81 invocations tools, drafting 0 candidat → pas de commit auto ; passe 6.5 a conservé les coherence-findings du run précédent — comportement d'archive observé, à surveiller). Spec P0 §§1-2-5 réécrite ; README kit/monorepo ; kit = `.opencode/` complet transposable.
- **v5.32.c** (15 août 2026, doctor tolérant) : config introuvable → **warning** (exit `1`) au lieu d'un exit `2` bloquant — le doctor poursuit son diagnostic avec défauts (`project_root` = cwd) ; l'installation incomplète reste visible, le run n'est plus bloqué à tort (mesuré au premier lancement du plugin : « warning config introuvable » puis « Kit OK »).
- **v5.32.b** (15 août 2026, modèle hors agent) : retrait du `model: opencode/deepseek-v4-flash-free`

- **v5.30** (14 août 2026, revue du run agent) : **deux magasins de métadonnées vivants** — sessions CLI (`opencode run`/TUI) dans `session`, sessions serveur/démon dans `session_v2` (mises à jour en continu, sans parts → `unflushed`). L'adaptateur `v1-dual` lit **`session` ∪ `session_v2`** (dédup par id, ligne la plus fraîche) + télémétrie `part`/`message` ; `detect_db` départage les égalités de `MAX(time_updated)` par priorité (v2 > v1-dual > v1-live > v1) — le tri `reverse=True` inversait aussi la priorité (corrigé). **Impact mesuré sur la même fenêtre 168h (ancre 16:04) : 0 → 19 sessions racines, $0 → $16,71, 112 M tokens, 44 touchées**. Le premier run agent lisait le miroir serveur → « 0 session » trompeur : la fenêtre était correcte, la table était la mauvaise.
